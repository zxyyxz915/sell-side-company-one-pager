# 公司公告与纪要知识库搭建

只完成资料检索、筛选、下载、去重、命名和登记。先搭好可追溯的基础资料库，再由其他任务进行业绩拆分或一页纸写作。

## 一、输入与截止日

开始前取得：

- 公司名称、证券代码及常用简称；
- 资料截止日 `T`；用户未指定时使用执行当日，并在结果中写明；
- 可访问的数据源及目标知识库位置。

为每家公司建立别名集合，包括中文全称、简称、曾用名、证券代码和英文名。所有时间窗口均从 `T` 倒推。

## 二、强制时间窗口

| 资料类型 | 检索与下载范围 |
|---|---|
| 重大经营公告 | 最近12个月全部检索；仍影响当前产能、项目状态或利润的历史事项追溯至首次披露 |
| 官方投资者关系活动记录 | 最近12个月检索；最近6个月必须尽量收全 |
| 官方业绩说明会、业绩发布会及问答 | 最近4个报告期或最近4场正式活动 |
| 券商调研、机构交流、管理层纪要 | 最近12个月检索，优先并收全最近6个月有效材料 |
| 知识星球、ima中的第三方纪要 | 最近6个月全部有效材料；更早资料仅在解释仍存续项目或最新指引时补充 |

不得把“最近半年最多5份”设为限制。最近6个月所有符合标准的有效经营纪要均应入库，数量控制只发生在后续引用或展示阶段。

## 三、来源顺序

按以下顺序检索和解决冲突：

1. 公司公告、交易所或巨潮资讯网原始披露；
2. 公司官网、官方IR页面、官方业绩说明会记录；
3. 政府部门或交易所资料；
4. Wind、iFinD等持牌数据库；
5. 具名券商研报或可追溯的券商/机构纪要；
6. 可追溯行业数据库；
7. 知识星球、ima中的第三方材料；
8. 财经资讯平台和搜索结果，仅用于发现原文。

ima是存储与检索层，不是证据等级。按其中原文件的发布主体判断来源。门户转载、搜索摘要和AI摘要不能替代原始文件。

## 四、公司公告筛选

### 必须保留

保留对当前经营或未来业绩存在实质影响的公告：

- 重大项目立项、建设、试生产、投产、停产、复产或退出；
- 新增、扩建、置换或关停产能；
- 重大收购、出售、增资、合资、重组或对外投资；
- 募投项目或融资安排发生实质变化；
- 重大合同、订单、长期供货协议；
- 产品价格、产销量、开工率或库存发生显著变化；
- 重大安全、环保、诉讼或政策事项，且可能影响生产经营；
- 业绩预告、业绩快报、业绩修正及重大会计口径变更；
- 对收入、成本、毛利或利润有明确影响的其他事项。

### 原则上排除

除非正文存在明确经营影响，否则不下载：

- 股东大会、董事会会议通知及普通决议；
- 分红、权益分派和常规治理文件；
- 普通人事变动、独立董事意见；
- 普通质押、担保、理财；
- 回购、减持或股权激励的日常进展；
- 股权激励解锁、归属及配套法律意见；
- 持续督导、财务顾问核查、章程修订、工商变更；
- 没有项目状态、金额、时间或经营影响变化的程序性进展。

不要按标题机械全收。对同一重大事项，原则上保留“首次披露—实质变化—最终落地”三个关键节点；其他重复进展仅登记但不重复入库。

## 五、纪要筛选

纪要至少包含一项定期报告之外的经营增量，才进入正式库：

- 最新产量、销量、订单、库存或开工率；
- 公司实现价格、调价、产品价差或价格趋势；
- 原材料、能源、运费、单位成本或成本变化；
- 新建产能、项目进度、投产和爬坡时间；
- 客户验证、产品导入、订单落地和新业务进展；
- 出口、区域、渠道或产品结构变化；
- 管理层对当期收入、毛利或利润变化的解释；
- 明确的下一阶段经营安排或指引变化。

以下纪要不进入正式库：

- 只重复年报、半年报或季报公开数字；
- 只有公司介绍、行业常识或长期愿景；
- 没有数字、时间点或具体经营事项的套话；
- 无法确认公司、活动日期或原始出处的聊天截图；
- 匿名传闻、二手转述或被后续正式披露否定的内容。

## 六、知识星球与高赞材料

把点赞量、收藏量和评论量仅作为发现重要材料的信号，不设未经用户确认的固定点赞门槛。

- 高赞且能确认公司、活动、日期和原始来源：按原来源等级入库；
- 高赞但缺少日期、作者、机构或活动信息：放入待核验区；
- 点赞较少但属于近期正式交流且有经营增量：仍应入库；
- 同一纪要被多人转载：保留最早、最完整、最接近原始活动的版本；
- 找到公司官方记录后，以官方记录为主，第三方纪要仅补充未公开的交流信息。

不得把高赞等同于真实，不得用热度覆盖来源核验。

## 七、真实性与元数据门槛

正式入库前必须确认：

- 目标公司与证券代码；
- 完整标题；
- 发布主体或纪要作者/机构；
- 活动日期与发布日期；
- 涉及的报告期或经营期间；
- 原始链接、原始文件或知识库路径；
- 文件类型；
- 是否存在更新版、修正版或更高等级来源；
- 影响主题，如产能、价格、成本、订单、项目或业绩。

缺少公司、日期或来源中的任一关键项时，不得进入正式库，只能进入待核验区。无法下载原文时登记链接、失败原因和待办状态，不得把搜索摘要冒充已下载原文。

## 八、去重与版本控制

执行以下规则：

1. 用“公司＋活动/事项＋日期＋发布主体”识别重复资料；
2. 官方原文优先于门户镜像，具名原始纪要优先于匿名转载；
3. 修正版替代旧版，但保留版本关系；
4. 同一场活动的文字、PDF和截图不得计为三份独立证据；
5. 文件名不同但正文一致的资料只保留一份主文件；
6. 不因多个转载同时出现而视为多源验证；
7. 原始文件必须保留，OCR、转写或摘要只能作为派生文件。

## 九、目录与命名

按公司建立以下目录：

```text
公司简称_证券代码/
├── 01_重大经营公告/
├── 02_官方IR与业绩说明会/
├── 03_券商与机构纪要/
├── 04_知识星球与其他可追溯纪要/
├── 90_待核验/
└── 99_资料清单/
```

文件名统一为：

```text
YYYYMMDD_公司简称_资料类型_核心事项_发布主体.ext
```

不得只用“最新纪要”“调研1”“截图”等无法识别的名称。

## 十、交付清单

每家公司输出一张资料清单，至少包含：

| 字段 | 要求 |
|---|---|
| 文件名 | 与实际入库文件一致 |
| 资料类型 | 公告、官方IR、业绩说明会、券商纪要、第三方纪要 |
| 活动日期 | 纪要对应的实际交流日期 |
| 发布日期 | 文件公开或转载日期 |
| 发布主体 | 公司、交易所、券商、机构或作者 |
| 原始来源 | URL、数据库路径或知识库文件标识 |
| 核心增量 | 一句话说明新增了什么经营信息 |
| 影响主题 | 产能、价格、成本、订单、项目、业绩等 |
| 入库状态 | 正式入库、待核验、重复、被替代、下载失败 |
| 关联版本 | 首次披露、实质进展、最终落地或修正版关系 |

最终汇报数量：正式入库多少份、待核验多少份、重复剔除多少份、下载失败多少份，并列出未覆盖的必需时间窗口。

## 十一、完成检查

只有同时满足以下条件才能称为完成：

- 最近12个月重大经营公告已检索；
- 最近12个月官方IR已检索，最近6个月已尽量收全；
- 最近4个报告期的官方业绩交流已检查；
- 最近6个月所有有效第三方经营纪要已收集，不设数量上限；
- 所有正式入库资料均能确认公司、日期和来源；
- 重复转载、旧版和配套附件已经处理；
- 待核验材料与正式材料分开；
- 下载失败和资料缺口已明确登记。

## 十二、红线

- 不杜撰不存在的公告、纪要、日期、作者或链接；
- 不把匿名传闻转写成公司事实；
- 不把搜索摘要、AI回答或新闻转述冒充原始资料；
- 不为凑数量保留无经营增量的文件；
- 不因资料缺失自行补数字、拼接不同期间口径或推测管理层表述；
- 不提前撰写一页纸、估值、盈利预测、产业链、风险提示或投资逻辑；
- 不删除原始文件后只保留摘要。

资料不足时如实输出缺口。空缺优于伪造，待核验优于错误入库。
